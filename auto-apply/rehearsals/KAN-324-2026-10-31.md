- KAN-458 Workday: 44 postings, 44 tenants. 35 stop at Create Account/Sign In (no account is made by an agent). 9 let a guest apply: each filled My Information, then the walk stopped on step 1 for three routine guesses (KAN-490), so Save and Continue was never reached. 3 of the 9 failed a prompt field (KAN-489). 1 false Applied on GE's Create Account page (KAN-485).

## No submit went out

Every non-GET request each page sent was logged. None was a submit: no Greenhouse, Lever or Workable application post, no Ashby submit operation, no Workday or Oracle submit path. What did go out before any submit, as each job system does for a person:

- résumé uploads for parsing (Greenhouse and Ashby S3 uploads, Lever's parseResume, Workable's upload), with the test résumé;
- Ashby's own field autosave (ApiSetFormValue), with the test student's values;
- on Workday's guest tenants, Apply Manually starts an unsent application and Workday saves each step field as it is filled (jobapplications, emailaddress, phonenumber, source). These are drafts with the test student's dummy data; none was sent.
- on Workday's Create Account pages, the extension typed the test email and a new password into the boxes (its sign-in help). Nothing pressed Create Account: the student's yes to "Let WorkIt Sign You In" was never given, so no account was made.

## Not checked

- Wrong answers: each filled field's read-back is checked by the engine (a field that shows something else fails). Values themselves were not read by a person.
- Written answers: the batch leaves essay and open questions to the student's Claude (connector). No Claude was connected, so they wait. That is counted as a correct Needs you.

## How it was run

- **Local WorkIt only.** The API ran on this computer (`auto-apply/rehearsals/stack/serve.py`) on a new Docker Postgres (`workit-kan324-db`), migrated to head. No Supabase call: its URL pointed at a closed local port, and the résumé was a local file (LOCAL_FILES_DIR). The 100 postings were read from WorkIt's public jobs feed (21,552 internships) and imported into that database.
- **Test student.** The extension tests' fixture student ("Test Person", test.person@example.com, dummy data), with a full set of autofill answers, a Stony Brook B.S. CS education entry, one past internship and a one-page dummy résumé. No account was made on WorkIt production or on any employer site.
- **Browser.** Headless Chromium with the unpacked extension (the test copy), a fresh profile per shard, through `autofiller_extension/test/live/rehearse.live.ts`: only localhost is faked (the API is passed through to the local one); every job system is real. Each batch of 5 opens as picks (`run/open` with job ids); each tab is recorded once its state and panel stay still for 15 s, its fill report is sent (Report a problem, Send), and the tab is closed.
- **Postings.** Chosen by job system share among the feed's auto-apply postings (Workday 44, Oracle 11, Greenhouse 9, iCIMS 8, TikTok 6, Ashby 5, Lever 5, Workable 5, Waymo 2, Rippling 2, no Filler 3). One posting per company (per tenant on Workday, Oracle, iCIMS), no job boards, posted in the last weeks. 5 shards of 20 to 22 ran in parallel.
- **Fill reports.** 99 sent (one tab had no panel), to the local API's fill_reports.

Per-posting results: `KAN-324-2026-10-31.json` (job system, URL, outcome, fields filled / to check / waiting / needs you, reason, fill report category and errors, ticket).
