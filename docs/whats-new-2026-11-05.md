## Apply: `worker_mode`

`worker_mode` selects the Worker that fills a form. Set it in `policies.yaml` in your data folder (`APPLY_HOME`). Do not change `policies.default.yaml` for your own runs.

- `cdp`: Chrome driven by Playwright. This is the default.
- `plain`: every form uses a plain Worker. A plain Worker is a Chrome with no CDP and no automation flags.
- `protected`: only the hosts in `plain_worker_hosts` and `plain-hosts.json` use a plain Worker.

Apply never evades bot detection and never touches a captcha. It hands those to the user.

Before you use `plain` or `protected`, run this command one time:

```sh
uv run apply plain seed
```

It opens Chrome on the seed profile and prints the steps. Do the steps by hand, then quit that Chrome. Run the command again only if a message tells you to.

## Apply: `apply rehearse --into`

A job site's sign-in stays only in the browser session. A new Chrome must sign in again. So send the next posting into the plain Worker that is running:

```sh
uv run apply rehearse <first link>
uv run apply rehearse --into <window port> <next link>
uv run apply rehearse --into <window port>:2 <link>
uv run apply rehearse --into <application id> <link>
```

The second form gets its own tab, tile and Record. It never submits. This works only on a plain Worker that is running.

## Apply: `apply ask`

Use `apply ask` to tell Claude what to fix on an open form:

```sh
uv run apply ask --list
uv run apply ask "<company, role or application ID>" "<your words>"
```

The form must be held or paused in a running Apply window. Do not drive the form yourself. Claude does not submit, tick an attestation box that you did not name, or type a password or code.

## Apply: page gates

`page_gates` is in `policies.yaml` in your data folder. The default is `false`.

- `true`: Claude fill stops on each page with a legal, consent, self-ID or unsure answer. Check the page, then press Resume.
- `note`: nothing stops. Each such field goes on the "Check before Submit" list.

Claude never ticks an attestation box and never signs. Oracle and Workday have no gates yet.

## Fill engine pointer

`autofiller_extension/fill-engine` is one pointer. The extension and Apply both use it.

- After each `git pull`, run `git submodule update --init --recursive`. A pull does not move your engine checkout.
- Merge the engine PR first. Point only at a commit on fill-engine `main`. A teammate cannot rely on a commit that is only on a branch.
- Move the pointer in its own commit: `KAN-<n>: Move the Fill engine to <the fix>`.
- Stage by path. Do not commit the pointer by accident when your engine checkout is on another commit.
- To test an engine branch without a move, set `APPLY_FILL_ENGINE` to that checkout.
- `dist/engine.js` is committed in the engine repo. It must match what `src/` builds, or CI fails.
