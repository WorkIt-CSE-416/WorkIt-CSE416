# shadcn/ui in WorkIt

How shadcn is wired into this repo, why it is wired that way, and how to pull a
component into a screen.

---

## 1. What shadcn actually is

The most common misunderstanding: **shadcn is not a component library you
install and import from.**

- **MUI, Chakra, Bootstrap** are a _vending machine_. You `npm install`, you
  `import { Button } from "@mui/material"`, and their code lives in
  `node_modules`. You can only customise what they chose to expose.
- **shadcn** is a _photocopier_. You run one command, and it copies the **source
  code** of a component into this repo as an ordinary file. From then on it is
  our file. We edit it like anything else, and nothing will change it behind our
  backs.

So there is no `import { Dialog } from "shadcn"`. There is
`import { Dialog } from "@/components/shadcn/dialog"` — a normal local import,
pointing at a file you can open and read.

Two consequences worth internalising:

- **Upgrades are not automatic.** Re-running `add` for a component overwrites
  our copy. That is a deliberate choice, not a bug.
- **The registry is not a dependency.** Browse it at
  <https://ui.shadcn.com/docs/components> like a catalogue.

### Why bother

Our `src/components/ui/*` primitives are good and they match the mockups. What
they don't have is the hard, invisible part of interactive widgets: focus
trapping, `Escape` to close, scroll locking, `aria-*` wiring, roving tabindex,
restoring focus to the trigger on close, keyboard navigation of a listbox.

That is what shadcn is for here. Use it for **Dialog, Select, Dropdown,
Popover, Combobox, Tabs, Tooltip, Sheet, Command** — things that are genuinely
hard to get right. Not for buttons and badges we already have.

## 2. How it is connected

### The base: Base UI, not Radix

`shadcn init` was run with `--base base --preset nova`, so the accessibility
engine underneath is **[Base UI](https://base-ui.com)** (`@base-ui/react`), not
Radix. Two things follow:

- Generated components import from `@base-ui/react/*`.
- Older tutorials and blog posts assume Radix and will not match our files
  exactly. The current <https://ui.shadcn.com> docs are the source of truth.

The `nova` preset pairs Lucide icons with Geist — which this project was already
using, so the fonts needed no change.

### What landed

| Added                      | Why                                                       |
| -------------------------- | --------------------------------------------------------- |
| `components.json`          | shadcn's config — where files go, which aliases to use    |
| `.mcp.json`                | Registers the shadcn MCP server for Claude Code           |
| `src/components/shadcn/`   | Where vendored components land                            |
| `@base-ui/react`           | Accessibility primitives underneath every component       |
| `lucide-react`             | Icon set the generated components import                  |
| `class-variance-authority` | How generated components express variants                 |
| `tw-animate-css`           | Enter/exit animations                                     |
| `shadcn`                   | Provides `shadcn/tailwind.css`, imported by `globals.css` |

### Three decisions that differ from a stock install

Anyone re-running `init` should know these, or they will be undone.

#### a. Components go in `src/components/shadcn/`, not `src/components/ui/`

`components.json` sets `aliases.ui` to `@/components/shadcn`.

Stock shadcn installs into `src/components/ui/` — which already holds our
hand-built, mockup-derived primitives. The very first `add dialog` tried to
**overwrite `ui/button.tsx`**, because shadcn's Dialog uses a Button for its
close control. That would have destroyed the variant set every screen depends on
(`primary`, `positive`, `quiet`, `ButtonLink`, `buttonClasses`).

Two folders, one rule:

- **`src/components/ui/`** — ours. Hand-written from the KAN-43 mockups. Prefer
  these. Edit freely.
- **`src/components/shadcn/`** — vendored. Regenerated by `shadcn add`. Treat as
  read-only unless you intend to fork a file permanently.

Because both folders can contain a `button.tsx`, an ESLint rule
(`eslint.config.mjs`) blocks app code from importing `@/components/shadcn/button`,
`badge`, or `card` and points you at the `ui/` one. The vendored copies exist
only so shadcn components can import each other.

#### b. `cn` comes from `@/lib/cn`, not `@/lib/utils`

`init` created a `src/lib/utils.ts` with a plain, unconfigured `cn`. It was
deleted and `components.json` now aliases `utils` to `@/lib/cn`.

This matters more than it looks. `src/lib/cn.ts` carries an
`extendTailwindMerge` config that teaches tailwind-merge about our custom
scales. Without it, `text-title text-ink` reads as two colours fighting and the
**font size is silently dropped**. A second, dumber `cn` in the codebase would
reintroduce that bug wherever it was used. Read the comment at the top of
`cn.ts` before touching it.

> If you add a design token, add it to the lists in `cn.ts` too. A missing entry
> is not a crash — it is a merge that quietly does nothing.

#### c. shadcn's colour names are aliased onto WorkIt's

shadcn components are written against a fixed vocabulary — `bg-primary`,
`text-muted-foreground`, `border-input` — that has nothing to do with our token
names. Rather than edit every component we pull in, the bottom of
`src/app/globals.css` maps one onto the other:

| shadcn role            | WorkIt token            | Value     |
| ---------------------- | ----------------------- | --------- |
| `--background`         | `--color-app`           | `#f8f8ff` |
| `--foreground`         | `--color-ink`           | `#121a28` |
| `--card`, `--popover`  | `--color-panel`         | `#ffffff` |
| `--primary`            | `--color-brand`         | `#005cff` |
| `--primary-foreground` | `--color-on-brand`      | `#ffffff` |
| `--secondary`          | `--color-surface`       | `#f8f8ff` |
| `--muted`              | `--color-well`          | `#f7f9fc` |
| `--muted-foreground`   | `--color-ink-meta`      | `#596980` |
| `--accent`             | `--color-brand-tint`    | `#e3ebff` |
| `--border`             | `--color-border`        | `#e3e9f0` |
| `--input`              | `--color-border-subtle` | `#e8ebf5` |
| `--ring`               | `--color-brand`         | `#005cff` |

**A stock shadcn component therefore renders in WorkIt's palette with no
editing.** That is the whole point of the mapping — don't restyle generated
components by hand.

Three lines `init` generated were removed, each for a reason recorded in
`globals.css`:

- `--color-border: var(--border)` — we already define `--color-border`
  (`#e3e9f0`). shadcn's block is emitted later in the file, so keeping this line
  repainted every existing `border-border` (the top bar, the login card, the
  work-history rail) in a neutral grey.
- `--font-sans: var(--font-sans)` — self-referential and redundant.
- The `--radius-sm … --radius-4xl` rebind — it reshaped `ui/badge.tsx`'s tag
  pill (6px → 8px) and `ui/text-link.tsx`'s focus ring (4px → 6px). Stock
  Tailwind radii are what existing call sites were measured against.

Still undesigned, holding shadcn's stock values: `--destructive` (WorkIt has no
red — no mockup draws a destructive action) and `--chart-1…5`. Both are marked
`OPEN` in `globals.css`.

### Dark mode

Not defined, on purpose — guessing a palette bakes in colours nobody designed.
`@custom-variant dark` is bound to a `.dark` **class** rather than the OS
setting, so shadcn's built-in `dark:` utilities stay inert instead of firing on
a visitor's system preference and painting dark utilities over a light-only
palette. Nothing sets that class.

## 3. Getting a component

### The short version

```bash
npx shadcn@latest add select
```

The file appears at `src/components/shadcn/select.tsx`. Import it:

```tsx
import { Select, SelectContent, SelectItem, SelectTrigger } from "@/components/shadcn/select";
```

That's it. It already matches WorkIt's colours.

### Look before you install

`add` can overwrite files. Always check first:

```bash
npx shadcn@latest add select --dry-run   # which files would change
npx shadcn@latest add select --diff      # what would change in each
npx shadcn@latest view select            # read the source without installing
npx shadcn@latest docs select            # usage examples and API
npx shadcn@latest search "date picker"   # find it when you don't know the name
```

`--dry-run` is the habit worth forming. It prints a `+N new, ~N overwrite`
summary, and **if it says anything would be overwritten, stop and ask** — that
means a name collision with something we wrote.

### Asking Claude Code instead

`.mcp.json` registers the shadcn MCP server, so Claude can search the registry,
read component source, and check docs directly. You can just say _"add the
shadcn combobox to the search filters"_ — no need to find it yourself or paste a
screenshot.

Screenshots are the worst way to ask for a component: they show the pixels but
not the behaviour, so what gets rebuilt from an image looks right and is quietly
broken for keyboard and screen-reader users. Name the component instead.

> The MCP server is picked up when Claude Code starts. If it isn't there,
> restart, and approve the server when prompted.

### After adding, always

```bash
npm run typecheck && npm run lint && npm run format
```

Generated files are not written to this repo's Prettier style, so `format` will
reformat them. That is expected — commit the result.

## 4. Rules of thumb

1. **Need a plain button, badge, card, input, chip, or link?** Use
   `src/components/ui/*`. Don't pull the shadcn equivalent.
2. **Need something interactive we don't have?** Pull it from shadcn.
3. **`--dry-run` first.** If it wants to overwrite, stop.
4. **Don't restyle a generated component to match the mockups.** If the colour
   is wrong, the token mapping in `globals.css` is wrong — fix it there and
   every component benefits.
5. **Don't hand-edit `src/components/shadcn/*`** unless you accept that the file
   is now forked and `add` will clobber it.
6. **Adding a design token?** Add it to `globals.css` _and_ to the lists in
   `src/lib/cn.ts`.

## 5. When something looks wrong

| Symptom                                                 | Likely cause                                                                 |
| ------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Component renders grey/black instead of WorkIt blue     | A role used by that component isn't mapped in `globals.css`                  |
| A Tailwind class in a `className` override does nothing | It isn't in the `cn.ts` merge lists, so tailwind-merge dropped the wrong one |
| ESLint: "import is restricted"                          | You imported the vendored `button`, `badge`, or `card`; use the `ui/` one    |
| `add` wants to overwrite a `ui/` file                   | `aliases.ui` in `components.json` got reset to `@/components/ui`             |
| Existing borders changed colour                         | `--color-border: var(--border)` came back into the `@theme inline` block     |
